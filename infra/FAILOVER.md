# Отказоустойчивость «Силы Рода»: основной сервер, запасной и DNS

Урок аварии 2 ноября 2026: у Beget были сразу сервер, DNS и регистратор
домена. Сервер упал — и вместе с ним пропала возможность направить домен
куда-то ещё. Зеркало подняли за несколько часов, но только на адресах
`*.sslip.io`, а часть данных (общий кабинет, руны, Таро, 20 вложений Рода)
осталась на упавшем сервере.

Цель схемы: **ни одна компания не держит всё сразу**, а переключение на
запасной сервер — одна команда и несколько минут.

## 1. Роли

| Что | Где | Почему |
|---|---|---|
| Основной сервер | HostVDS, 31.56.197.168 (сейчас зеркало) | уже работает, 2 ядра / 4 ГБ |
| Запасной сервер | Beget (после восстановления), минимальный тариф | другая компания, другой дата-центр |
| DNS | отдельный DNS-сервис с API (не Beget и не HostVDS) | переключение не зависит от серверов |
| Регистратор домена | отдельный регистратор (не Beget) | панель домена доступна при любой аварии хостинга |
| Резервные копии | Telegram (личный чат) + запасной сервер | две независимые копии вне основного сервера |
| Почта info@ | пока Beget; MX-записи переносятся в новый DNS как есть | см. п. 6 |

DNS и регистратор — **разные** компании, отличные от обоих хостингов.
Подходят российские сервисы с API и бесплатным или копеечным DNS (Selectel
DNS-хостинг, Яндекс Cloud DNS; регистратор — RU-CENTER или REG.RU).
Конкретные цены и условия — проверить при подключении.

## 2. DNS: короткий TTL и записи как код

- **TTL 300 секунд** (5 минут) для A-записей `@`, `www`, `plamya`, `rod`,
  `taro`, `runes`. После переключения адреса весь интернет увидит новый IP
  за 5–10 минут. MX, SPF, DKIM — обычный TTL (3600).
- Зона описана в репозитории: `infra/dns/zone.json` (план). Скрипт
  `infra/dns/apply.sh` (план) сверяет её с DNS-сервисом через API и меняет
  только A-записи. Токен API — только на серверах, в `/etc/sr-dns.env`.
- Переключение одной командой (план):

      bash /var/www/prod/infra/failover.sh to-standby   # домен → запасной
      bash /var/www/prod/infra/failover.sh to-primary   # домен → основной

  Команду можно запустить с любого из двух серверов: каждому нужен только
  токен DNS и копии данных.

**Если недоступен сам DNS-сервис** (как было с Beget): у домена два набора
NS — у основного DNS-сервиса и у второго (secondary, копия зоны по AXFR или
вторая зона того же содержания). Резолверы спрашивают любой из живых.
Последний рубеж — адреса `*.IP.sslip.io`: они работают без нашего DNS
вовсе. Их список держать готовым (п. 7) и сообщать ученицам заранее.

## 3. Запасной сервер: «тёплый» вместо «выключенного»

Выключенный VPS у большинства хостингов **продолжает тарифицироваться**
(диск и IP за ним закреплены), а «поднять актуальную версию в нужный
момент» с нуля — это те же часы, что 2 ноября. Поэтому два варианта:

**А. Тёплый резерв (рекомендуется).** Запасной сервер на минимальном тарифе
Beget (1–2 ГБ). На нём стоят все курсы, но **службы остановлены** и nginx
показывает только страницу «технические работы» на случай, если DNS
случайно укажет туда. Дважды в день, после копий (8:00 и 23:00 по Москве),
запасной сервер:

1. забирает свежие копии с основного (по SSH-ключу, только чтение);
2. обновляет код из GitHub (main) и пересобирает;
3. **восстанавливает копии в свои базы** и проверяет, что базы не пустые;
4. пишет в Telegram «резерв актуален на 08:05, Род: 7 учениц, школа: 5…».

Так запасной всегда отстаёт от основного не больше чем на 12 часов, и
каждые полдня проверяется, что копии действительно восстанавливаются —
то, чего не хватило 2 ноября. Переключение: `failover.sh to-standby`
запускает службы и меняет A-записи — **5–10 минут**.

**Б. Холодный резерв (дешевле, дольше).** Запасного сервера нет. При аварии
арендуется любой VPS (HostVDS, Timeweb — 5 минут), и один скрипт
`infra/vps/bootstrap.sh` (план, на основе `flame-app/deploy/mirror.sh`,
`infra/vps/mirror-courses.sh`) ставит всё и восстанавливает последние копии
из Telegram/с компьютера. Время — **30–60 минут**, деньги — только за
дни аварии.

Если Beget при восстановлении позволит «заморозить» VPS без оплаты — это
вариант Б с готовой машиной: размораживаем, затем шаги 1–3 тёплого
резерва вручную.

## 4. Что и как часто копируется

| Данные | Сейчас | Нужно |
|---|---|---|
| Базы Рода, школы, кабинета, рун, Таро | 8:00 и 23:00 МСК, Telegram | + запасной сервер |
| Вложения Рода, фото школы, медиатека | там же, целиком | целиком на запасном (rsync), в Telegram — только изменения |
| Настройки (.env, токены) | **не** копируются (открытым текстом в Telegram нельзя) | на запасном — свои, заводятся один раз при установке |
| Код | GitHub | — |

Чем чаще копии, тем меньше теряется при аварии. Между 23:00 и 8:00 —
9 часов. Если это много, добавить ночную копию в 3:00 (только базы — они
маленькие).

## 5. Переезд домена на новый сервер (когда Beget вернётся)

Порядок важен: сначала данные, потом DNS. Иначе ученицы вернутся на
сервер, где нет их записей последних дней.

1. **Забрать с Beget всё, чего нет на новом сервере** (Beget — только
   чтение, ничего не запускать):
   - базы рун (`/var/lib/runes/runes.sqlite`), Таро (`/var/lib/polkas/cabinet.db`),
     общего кабинета (`/var/lib/sr-accounts/accounts.sqlite`), бота
     (`/var/lib/rodbot/bot.sqlite`);
   - медиатеку редактора лендинга (`/var/lib/sr-accounts/media/`);
   - вложения Рода (`/var/www/rodology/server/storage/uploads/`) — те самые 20 файлов;
   - фото школы (`/var/www/flame-app/public/uploads/`);
   - свежие дампы flame_db и rodology — на момент падения (2 ноября, 02:45).
2. **Свести данные двух серверов.** На новом сервере с 1–2 ноября идут
   свои записи (отчёты, ДЗ, дневники), на Beget — записи с момента ночной
   копии до падения. Скрипт сведения (план, `infra/vps/merge-beget.sh`):
   добавляет в базы нового сервера строки Beget, созданные после времени
   копии, по которой поднято зеркало; совпадения по id — пропускает и
   показывает списком. Руны, Таро, кабинет: на зеркале они без данных —
   берутся с Beget целиком.
3. **Включить общий вход** на новом сервере с базой кабинета с Beget и
   вернуть Род на вход через общий кабинет (`SR_INTERNAL_SECRET`) — тогда
   временные пароли зеркала больше не нужны.
4. **Сертификаты для belayarod.ru** на новом сервере: выпуск по DNS-проверке
   (certbot `--preferred-challenges dns`) — можно до переключения A-записей.
5. **DNS**: перенести зону в новый DNS-сервис (п. 2), все записи как у Beget,
   **MX/SPF/DKIM почты — без изменений**, A-записи → 31.56.197.168, TTL 300.
   Затем у регистратора сменить NS домена на новый DNS-сервис.
6. **Проверка** с компьютера и телефона: belayarod.ru, кабинет, школа, Род,
   руны, Таро, вебхуки ботов (переустановить на `belayarod.ru`).
7. **Beget-сервер** — в роль запасного (п. 3): остановить службы, снизить
   тариф, настроить забор копий.
8. **Перенос домена** к другому регистратору — отдельно, после стабилизации
   (передача .ru занимает до недели, сайт при этом работает).

## 6. Почта

`info@belayarod.ru` живёт у Beget. При переносе DNS MX-записи остаются
указывать на Beget — почта продолжит работать, пока Beget работает. Чтобы
при следующей аварии Beget не пропала и почта — перенести ящик к почтовому
сервису, не связанному с хостингом (Яндекс 360, Mail.ru для бизнеса);
настройки — `infra/MAIL.md`.

## 7. Памятка на случай аварии

| Что случилось | Что делать | Время |
|---|---|---|
| Упал основной сервер | `failover.sh to-standby` на запасном | 5–10 мин |
| Упал DNS-сервис | ничего: работает второй набор NS | 0 |
| Упали оба DNS | ученицам — адреса `plamya.IP.sslip.io`, `rod.IP.sslip.io` (бот, рассылка) | 15 мин |
| Упал запасной | ничего срочного; поднять новый по варианту Б | — |
| Потеряны данные | восстановить из Telegram (`infra/BACKUP-RECOVERY-VPS.md`) | 30–60 мин |

Раз в месяц — **учения**: переключиться на запасной в спокойное время,
проверить вход и уроки, вернуться. Без учений резерв — только надежда.
