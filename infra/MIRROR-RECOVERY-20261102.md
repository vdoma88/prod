# Аварийный сервер: порядок восстановления

Новый сервер: 31.56.197.168. Сначала лендинг из vdoma88/prod и служба общего кабинета, затем «Связь с Родом» и «Язык Пламени». Таро и руны — последними.

## Лендинг и кабинет

В SSH под root:

    cd /var/www
    if [ ! -d prod/.git ]; then git clone --branch main https://github.com/vdoma88/prod.git prod; fi
    MIRROR_IP=31.56.197.168 bash /var/www/prod/infra/vps/restore-mirror-hub.sh

Результат при успешном исполнении:
- Лендинг: https://31-56-197-168.sslip.io/
- Общий кабинет: https://31-56-197-168.sslip.io/account/
- Род: https://rod.31-56-197-168.sslip.io/
- Свечи: https://plamya.31-56-197-168.sslip.io/

Скрипт использует prod/main, собирает dist, изменяет ссылки в собранном зеркале, создаёт отдельный nginx-хост mirror-hub и запускает sr-accounts на 127.0.0.1:4320. Он не меняет действующие vhost mirror для Рода и Пламени, не удаляет базы и не переносит DNS основного домена belayarod.ru. Таро и руны пока оставлены с прежними адресами, до своей очереди.

Чтобы создать администратора нового общего кабинета, повторно запустить этот же сценарий с переменными ADMIN_EMAIL и ADMIN_NAME. Ссылка для задания пароля показывается только в локальном терминале.

**Нельзя восстановить из GitHub:** базу аккаунтов /var/lib/sr-accounts/accounts.sqlite, опубликованные правки лендинга и загруженные через визуальный редактор изображения /var/lib/sr-accounts/media/. Нужны резервные копии со старого VPS. Существующие пользователи Род не получат общий вход автоматически. Не включать SSO до сверки аккаунтов, чтобы не заблокировать учениц.

## Школа свечей

Проверенная база flame_recovery_20261101 содержит 5 пользователей, 33 урока, 25 домашних работ и 44 записи дневника. Основная flame_db после неудачного импорта пустая. Для контролируемого переключения:

    bash /var/www/prod/infra/vps/restore-mirror-flame-db.sh

Сценарий проверит реальные учётные данные приложения, количество записей, восстановит изображения без перезаписи, сохранит резервную копию .env.local, переключит DATABASE_URL и перезапустит flame-school. При сбое локального HTTP-проверочного запроса вернёт настройки назад. После исполнения обязательно проверить вход, уроки, ДЗ и изображения в браузере.

## Род

В базе rodology восстановлено 7 пользователей и 6 клиентов. Нужно дополнительно проверить вложения /var/www/rodology/server/storage/uploads и таблицу File. Не импортировать дамп повторно поверх рабочей базы, не создавать массово новые пароли и не подключать SSO до восстановления аккаунтов.

## Проверка без секретов

    nginx -t
    systemctl is-active nginx sr-accounts rodology flame-school
    curl -k -s -o /dev/null -w 'rod: %{http_code}\n' --resolve rod.31-56-197-168.sslip.io:443:127.0.0.1 https://rod.31-56-197-168.sslip.io/
    curl -k -s -o /dev/null -w 'plamya: %{http_code}\n' --resolve plamya.31-56-197-168.sslip.io:443:127.0.0.1 https://plamya.31-56-197-168.sslip.io/
    curl -k -s -o /dev/null -w 'hub: %{http_code}\n' --resolve 31-56-197-168.sslip.io:443:127.0.0.1 https://31-56-197-168.sslip.io/

HTTP 200 подтверждает ответ сервера, но не корректную работу входа, прав пользователей и учебного контента. В конце проверьте все три адреса с компьютера. Не переключать публичный DNS belayarod.ru до успешной проверки зеркал.
