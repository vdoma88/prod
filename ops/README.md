# Пульт «Силы Рода» в Telegram

Одно сообщение в личном чате с ботом, которое само показывает состояние
сервера (ноябрь 2026, после аварии Beget):

- службы и сайты: школа, Род, общий кабинет, руны, Таро, бот, nginx, база;
- свежесть резервных копий каждого курса (`/root/sr-backups`);
- сколько ждут проверки: шаги Рода, ДЗ школы, отливки;
- диск, память, нагрузка;
- кнопки «Обновить» и ссылки в кабинеты Рода, школы и общий кабинет.

Сообщение — **виджет Telegram** (мини-HTML в сообщении, Bot API 10.4,
[TelegramMessenger/widget-sandbox](https://github.com/TelegramMessenger/widget-sandbox)).
Бот обновляет его каждые 5 минут; «Обновить» и каждое открытие чата
запрашивают свежие данные сразу. Тревога (упала служба, копия старше 16 ч,
диск ≥ 90 %) и «снова в порядке» приходят обычным сообщением.

Пока виджеты в бете, обычный Telegram их не показывает: `/status` присылает
ту же сводку текстом, `/pult` при отказе Telegram — тоже текст.

| Файл | Что |
|---|---|
| `status.mjs` | опрос сервера (только чтение) → состояние; `packStatus` — в 1024 байта chatData виджета; `statusText` — текстом |
| `widget.html` | виджет: ≤ 32 КБ, ≤ 4 КБ сжатый (сейчас ~2,3 КБ), профиль 1 — только кнопки, без сети |
| `bot.mjs` | бот: `/pult`, `/status`, ответ на «Обновить» (`widget_query` → `answerWidgetQuery`), плановое обновление (`editMessageWidgetData`), тревоги |
| `deploy/sr-ops.service` | служба systemd |
| `test/ops.test.mjs` | `npm run test:ops` |

Установка и обновление на сервере: `bash /var/www/prod/infra/vps/install-ops-widget.sh`
(настройки — `/etc/sr-ops.env`, только root). Пульт видят только Telegram ID
из `OPS_ADMIN_IDS`; остальным бот отвечает, что он служебный.

Состояние виджета (`chatData`, JSON): `t` время МСК, `d` домен для ссылок,
`s` `[[имя, 1|0]]` службы и сайты, `b` `[[имя, часов|null, 1|0]]` копии,
`q` `[Род, ДЗ, отливки]` (null — не узнать), `m` `[диск, память, нагрузка]` %,
`a` число тревог.
