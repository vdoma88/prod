# Лендинг belayarod.ru

Лендинг — статический сайт в `site/`. Это **источник истины**: бывший
`vdoma88/landos` скопирован и дальше живёт здесь, поверх `site/` его копировать
нельзя. Заявки идут только через Telegram. Общий контекст и список приложений —
в `CLAUDE.md`, дизайн — в `brand/DESIGN.md` (при расхождении прав `brand/tokens.css`).

## Прежде чем править

1. Правка текста или фото — это не всегда работа для кода. Тексты и фото
   администратор меняет сам: https://belayarod.ru/account/ → «Редактировать
   тексты сайта». Код правим, когда нужно новое место, новая страница, структура,
   стиль или поведение.
2. Не гадай, что на странице сейчас: прочитай нужный файл в `site/`.
3. Дизайн уже задан. Новая страница должна выглядеть как остальные: токены из
   `brand/`, никаких чужих стилей и внешних `DESIGN.md`. Интонация: спокойно, без
   давления, без таймеров, мигающих плашек и «успей купить».

## Что где лежит

| Файл | Зачем |
|---|---|
| `index.html`, `compact-home.css/js` | главная: шесть карточек, раскрытие всех девяти направлений, фильтры. Без JS все девять карточек видны и ведут на отдельные страницы |
| `courses.html` | «Мои курсы» — вход во все кабинеты |
| `therapy.html`, `candle-course.html`, `tarot-course.html`, `runes.html` | курсы с кабинетом (rod / plamya / taro / runes `.belayarod.ru`) |
| `mystery.html`, `game.html`, `offerings.html`, `massage.html`, `consultations.html` | направления без кабинета |
| `styles.css`, `direction-pages.css`, `archaic-pages.css` | стили |
| `app.js` | меню, FAQ, окно заявки, подбор формата, фильтр каталога |
| `drum.js` | бубен на главной |
| `boot.js`, `landing-editor.js`, `landing-visual.js` | подмена текстов и фото из редактора администратора |

`robots.txt` и `sitemap.xml` не пишем руками — их создаёт `scripts/build.mjs`.
Телеметрию даёт общий `brand/sr-pulse.js`, он стоит на каждой странице
**раньше** `app.js`.

## Железные правила

- **Строгий CSP.** Нет `style="…"`, нет `on*="…"`, нет встроенных `<script>`.
  Стили — в CSS-файлах, обработчики — через `addEventListener`. Картинки
  только со своего сайта и `data:`; `blob:` CSP блокирует.
- **Никакого `innerHTML`** с чужим или пользовательским текстом: `textContent`
  и `createElement`.
- **Без внешних изображений и скриптов.** Картинки — в `site/assets/`.
- **Заявка — только Telegram.** Форм с отправкой на другой адрес и почтовых
  форм не заводим.
- Сломанная страница без JavaScript — ошибка: главная и каталог должны
  работать и без него.
- Тексты для людей — по-русски, без канцелярита. Имя — **Екатерина Белая**
  (не «Катерина»).
- Тронул `brand/` — подними версию (`package.json`, `VERSION`, шапки файлов,
  `sr-brand.js`, `tokens.css`), иначе `check.mjs` не пройдёт. Потом
  `npm run sync-brand`: бренд попадает в приложения копией.
- Всё, что касается `flame-app`, делаем осторожно: там идут занятия.

## Типовые задачи

### Добавить или изменить страницу направления

1. Страница — копия соседней в `site/`, те же шапка, подвал и порядок
   скриптов (`sr-pulse.js` раньше `app.js`).
2. Направление с кабинетом: запись в `PROJECTS` в `brand/sr-brand.js` — это
   единственный список курсов. `check.mjs` требует для каждого курса страницу,
   ссылку «войти» на ней и карточку на `courses.html`.
3. Кнопка `data-service` должна быть в списке направлений окна заявки, а список
   одинаков на всех страницах.
4. Добавь страницу в `pages` в `landing-editor.js` (иначе администратор не
   сможет править её тексты) — с названием, как на сайте.
5. Все локальные ссылки и картинки должны вести на существующие файлы.

### Новая страница или переписанная структура

Перед работой прочитай соседний скилл `landing-page-design`
(elayadesign/ai-design-skills, MIT). Бери из него часть A (вопросы заранее,
порядок секций, выбор макета, правила текста, SEO), а также B7–B10. Его
визуальные правила (шрифты, отступы, тёмные фоны, градиенты, Tailwind) у нас
**не действуют**: дизайн задан в `brand/DESIGN.md`. Оговорка на этот счёт
написана в самом скилле. Не давай давления («успей», таймеры, скидки на время).

### Править текст

Если текст нужно поправить один раз — лучше отдать это администратору.
Если правишь в коде: помни, что правки администратора привязаны к
**месту в разметке** и к исходному тексту. Поменяешь HTML — часть его правок
станет «устаревшей» (видна в панели редактора) или найдётся по исходному
тексту; нет текста — правка не применится. Поэтому переписывая блок, который
администратор мог править, скажи об этом.

### Фото и объекты

- Обычное фото: файл в `site/assets/` (WebP, без лишнего веса) и `alt`.
- Администратор в режиме редактирования заменяет фото, масштабирует, скрывает
  блоки и картинки. Загруженные им файлы хранятся **не в `dist/`**, а в
  `/var/lib/sr-accounts/media/` (`/account/media/<sha256>.webp`) и входят в
  резервную копию вместе с `accounts.sqlite`. SVG и сторонние ссылки загрузить
  нельзя.
- Новый блок, который нужно уметь скрывать или переставлять, должен попасть в
  `blockQuery` в `landing-visual.js`; адрес элемента не длиннее 240 знаков.

### Редактор не работает

Читай `landing-editor.js`, `landing-visual.js` и серверную часть
`accounts/landing.mjs`. Проверь в Safari отдельно: он тихо отдаёт PNG там, где
просили WebP, поэтому загрузка читает файл через `FileReader` (`data:`).

## Проверки

```
npm test
```

Собирает сайт, запускает `scripts/check.mjs` (все страницы, ссылки, CSP,
версия бренда, синтаксис JS), тесты бота и входа, живую проверку.

```
npm run test:e2e
```

Браузерный тест — запускай при любой правке `site/` и `brand/`, по возможности
на телефонной ширине тоже.

Для быстрой проверки исходников без сборки: `node scripts/check.mjs --sources`.
Посмотреть сайт локально: `npm run serve`.

Если правка визуальная — сними скриншоты (компьютер и телефон) и посмотри
их, прежде чем говорить «готово».

## Выкладка

Работаем веткой: ветка → проверки → скриншоты → pull request. В `main` — только
по команде владельца. Сам `dist/` в git не лежит (`dist/` в `.gitignore`).

На сервере (владелец выполняет по одной строке; терминал отрезает `&&`, `$`,
`|` и кавычки, поэтому команды — строго по одной):

```
cd /var/www/prod
```
```
sudo bash infra/update.sh
```

Скрипт обновляет `main` (только fast-forward, при локальных правках на сервере
останавливается), проверяет исходники, **подменяет `dist/` целиком**, проверяет
и перезагружает nginx, перезапускает бота и общий вход, а в конце сверяет, что
опубликован именно ожидаемый коммит. Не прошла проверка — `dist/` остаётся
прежним. После слияния PR всегда напомни владельцу запустить обновление.

## Чего не делать

- Не копировать `landos` поверх `site/`.
- Не добавлять inline-стили и скрипты «на минутку».
- Не вшивать токены и секреты; заявки идут через бота.
- Не показывать токен бота в чате.
- Не менять `PROJECTS` без обновления страницы, карточки и списка заявок.
- Не говорить «готово», не запустив `npm test`.
